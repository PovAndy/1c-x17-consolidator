## Что уже полезно для задачи новых счетчиков

### Уже используем
1. `dump-config.win.ps1`
- распаковка `x1_14` для анализа конфигурации

2. `copy-config-dump-to-linux.sh`
- перенос распакованного дампа в Linux-копию проекта
- нужен, потому что прямое чтение `Configuration.xml` и больших веток из `/mnt/c/...` может быть медленным или упираться в `Permission denied`

2. адресная диагностика в EPF
- сравнение `x17` и `x1-14` по одному ЛС

3. `sql_ro_query.py`
- безопасные read-only SQL-проверки по `MergedBase`

### Что стоит подключать дальше
1. `web-test`
- если понадобится воспроизводить расчет через веб-клиент и собирать шаги автоматически

2. `probe-consumer-report-issues-com.win.ps1`
- как источник готовых приемов по расчетным регистрам и комментариям начислений

3. `probe-doc-izmenenie-uslug-metadata.win.ps1`
- для точного понимания структуры документа изменения услуг

4. `inspect`
- уже полезен на локальной копии `x1_14_local` для фиксации владельцев ИПУ, структуры документов и регистраторов

## Что уже установлено по конфигурации x1_14
1. маршрут расчета по новым счетчикам идет не через `икУслугиЛицевыхСчетов`, а через приборный слой
2. ключевой промежуточный источник для начислений:
- `РегистрНакопления.икОбъемПотребленияПоПриборамУчета`

3. критичные общие модули:
- `икПриборыУчета`
- `икНачисления`
- `икРасчетНачислений`

4. ключевые функции:
- `икНачисления.ПолучитьПриборыУчета(...)`
- `икПриборыУчета.ПолучитьПредыдущееПоказаниеПрибораУчета(...)`
- `икПриборыУчета.ПолучитьОбъемПотребленияПоПриборамУчета(...)`

5. для восстановления начислений по новым счетчикам в `x17` нужно лечить именно:
- `икПоказанияПриборовУчета`
- `икСтатусыПриборовУчета`
- `икОбъемПотребленияПоПриборамУчета`

а не повторно переигрывать `икУслугиЛицевыхСчетов`
