# Следующий Этап: Живые Дубли ПВХ

## Что подтверждено после 118.32

- `икХарактеристикиОбъектовУчета`: `11` групп, `30` активных элементов в дубль-группах
- `икХарактеристикиПрочихОбъектов`: `5` групп, `11` активных элементов в дубль-группах

## Операционный порядок

1. сначала закрыть ручной хвост broken refs `29`
2. затем повторно снять контрольную диагностику broken refs
3. после этого снять свежую диагностику живых дублей
4. сначала схлопывать активные дубли в `икХарактеристикиПрочихОбъектов`
5. затем схлопывать активные дубли в `икХарактеристикиОбъектовУчета`
6. только после этого запускать обычное удаление помеченных объектов, на которые уже нет ссылок

## Приоритет

1. активные дубли `икХарактеристикиПрочихОбъектов`
2. активные дубли `икХарактеристикиОбъектовУчета`
3. только после этого физическая чистка уже помеченных на удаление дублей

## Почему не надо удалять помеченные дубли прямо сейчас

- помеченные на удаление элементы уже не главный блокер;
- основной риск сейчас сидит в живых активных дублях;
- массовое физическое удаление правильно делать только после очистки ссылок и схлопывания активных дублей.

## Правило для оператора

1. если дубль уже помечен на удаление и на него больше нет живых ссылок, его можно удалить штатным удалением помеченных объектов;
2. если элемент предопределённый или на него ещё есть ссылки, удалять его вслепую нельзя.

## Что идёт следующим слоем после ПВХ

После завершения слоя живых дублей ПВХ следующим отдельным блоком нужно поднимать:

1. дубли индексов/кодов/идентификаторов в критичных справочниках;
2. дубли документов и конкурирующие документные истории.

Правило для этого слоя:
1. сначала нужна инвентаризация и оценка реального риска;
2. массовый corrective-pass делать только по тем дублям, которые реально участвуют в логике, отчетах, начислениях или выборе объекта.
