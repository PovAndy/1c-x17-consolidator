# План безопасной дедупликации услуг и справочников приборов x17

Дата: 2026-04-24
Статус: аналитический план, без применения исправлений.

## Зачем пересматривать порядок

Оставшиеся элементы вида `Домовой счетчик (13)` не являются простым дублем только справочника `икВидыПриборовУчета`.
После ужесточения правила в `v25-120.26` кандидатов не найдено, потому что у похожих видов приборов различаются связанные `ВидУслуги` и/или профиль этой услуги.
Следовательно, корректная дедупликация должна идти снизу по зависимостям, а не сразу по виду прибора.

## Цепочка зависимостей

1. `икСправочникиГИСЖКХ`
   - Используется как `икВидыУслуг.ВидКоммунальногоРесурсаГИСЖКХ`.
   - Иерархический справочник с предопределённой веткой `ВидыКоммунальныхРесурсов`.
   - Имеет реквизиты `РеестровыйНомерСправочника`, `ГруппаСправочника`, `НаименованиеПолное` и табличные части `РеквизитыСправочника`, `ЗначенияРеквизитаСТипомПеречисление`.
   - Используется широко в ГИС ЖКХ, закрытии ЛС, снятии объектов, загрузке/выгрузке приборов и платежных документов.
   - Вывод: глобально объединять весь справочник нельзя. Автоматически допустима только узкая ветка `Виды коммунальных ресурсов` и только при совпадении полного профиля.

2. `икГруппыУслуг`
   - Используется как `икВидыУслуг.ГруппаУслуг`.
   - Также используется в `икСоглашениеОРассрочке` и отчётах через `Услуга.ВидУслуги.ГруппаУслуг`.
   - Реквизит: `ПорядокВОтчетах`.
   - Вывод: объединять можно раньше `икВидыУслуг`, но только по нормализованному имени, родителю/иерархии и `ПорядокВОтчетах`.

3. `икВидыУслуг`
   - Реквизиты профиля: `ГруппаУслуг`, `ВидКоммунальногоРесурсаГИСЖКХ`, `КапитальныйРемонт`, `ЭтоОтопление`.
   - Используется напрямую в `икУслуги`, ТЧ `икУслуги.ВидыУслуг`, `икВидыПриборовУчета`, документах субсидий/предоставления услуг и обработках ввода/загрузки приборов.
   - Вывод: объединять только после нормализации ссылок на группы услуг и ГИС-ресурсы. Ключ безопасности должен использовать канонизированные ссылки зависимостей, а не сырые ссылки.

4. `икВидыПриборовУчета`
   - Реквизиты профиля: `ВидУслуги`, `ЕдиницаИзмерения`, `ПриборУчитываетПоказанияНесколькихТарифныхЗон`, `РазрядностьПрибораУчета`, `ТипПоказанийПрибораУчета`, `МаксимальноДопустимаяВеличинаПоказаний`, `Точность`, `БлокироватьВводПоказанийНаСтороннихРесурсах`.
   - Используется в индивидуальных/коллективных приборах, услугах, настройках загрузки/выгрузки, документах показаний.
   - Вывод: это последний слой. Объединять можно только после нормализации `икВидыУслуг`.

5. `икТипыПриборовУчета`
   - Простое имя/код без реквизитов профиля.
   - Используется в индивидуальных/коллективных приборах и настройках загрузки.
   - Вывод: можно чистить отдельно, но желательно после отчёта по фактическому использованию, чтобы не ломать операторские различия.

6. `икУслуги`
   - Критичный расчётный справочник, содержит `ВидУслуги`, настройки начислений, нормы, основания, ТЧ `ВидыПриборовУчета`, `ВидыУслуг`, зависимые/основные услуги.
   - Вывод: не включать в автоматическую дедупликацию на этом этапе. Только диагностировать влияние после нормализации видов услуг/приборов.

## Проверенные критичные места кода

1. Загрузка приборов из ГИС ЖКХ подбирает ресурс через:
   - `Справочники.икСправочникиГИСЖКХ.НайтиПоНаименованию(ВидРесурсаСтрока,,Справочники.икСправочникиГИСЖКХ.ВидыКоммунальныхРесурсов)`.
   - Значит дубли внутри ветки `ВидыКоммунальныхРесурсов` напрямую влияют на подбор вида прибора.

2. Подбор вида прибора в загрузке ГИС идёт по:
   - `икВидыПриборовУчета.ВидУслуги.ВидКоммунальногоРесурсаГИСЖКХ`.
   - Значит разные ссылки на одинаковую `Холодную воду` делают разные виды приборов несовместимыми для текущего строгого `[11]`.

3. Платёжные документы и выгрузки ГИС используют ветку:
   - `Родитель = ЗНАЧЕНИЕ(Справочник.икСправочникиГИСЖКХ.ВидыКоммунальныхРесурсов)`.
   - Значит нельзя переносить/удалять элементы вне этой ветки без отдельного анализа.

## Правильная последовательность работ

1. Диагностика полной цепочки без изменений.
   - Вывести группы дублей `икГруппыУслуг`.
   - Вывести группы дублей `икСправочникиГИСЖКХ` только в ветке `Виды коммунальных ресурсов`.
   - Для каждого `икВидыУслуг` показать сырой профиль и канонизированный профиль после предполагаемой нормализации зависимостей.
   - Для каждого `икВидыПриборовУчета` показать, почему он не схлопнулся в `[11]`: отличается `ВидУслуги`, ресурс ГИС, группа услуги, единица, тип показаний или другой реквизит.

2. Нормализация `икГруппыУслуг`.
   - Перепривязать ссылки через `ОбщегоНазначения.ЗаменитьСсылки`.
   - Дубли пометить на удаление и переименовать с префиксом `ДУБЛЬ`, как в существующем механизме `Адапт_ОбработатьПорциюЗамен`.
   - Не удалять физически.

3. Нормализация узкой ветки `икСправочникиГИСЖКХ.ВидыКоммунальныхРесурсов`.
   - Сначала группы/папки, затем элементы ресурсов.
   - Безопасный ключ: это группа/элемент, родитель/канонический родитель, нормализованное имя, код/реестровый номер, `ГруппаСправочника`, `НаименованиеПолное`, табличные части.
   - Если табличные части отличаются, только отчёт без автоисправления.

4. Нормализация `икВидыУслуг`.
   - Ключ: нормализованное имя + каноническая группа услуг + канонический ГИС-ресурс + `КапитальныйРемонт` + `ЭтоОтопление`.
   - Все отличия вывести в отчёт как блокированные группы.

5. Повторная диагностика и исправление `[11]` по `икВидыПриборовУчета` и `икТипыПриборовУчета`.
   - После нормализации вида услуги оставшиеся элементы `Домовой счетчик (13)` должны стать либо безопасными кандидатами, либо явно объяснёнными различиями.

6. Контроль после исправлений.
   - Визуально: `Справочники -> Индивидуальные приборы учета -> открыть проблемный счетчик`.
   - Поле `Вид прибора учета` должно ссылаться на активный канонический элемент без служебного номера, если профиль действительно совпал.
   - Списки выбора `Виды приборов учета`, `Типы приборов учета`, `Виды услуг`, `Группы услуг`, `Справочники ГИС ЖКХ -> Виды коммунальных ресурсов` должны показывать дубли как помеченные и с префиксом `ДУБЛЬ`.
   - Расчёт: создать/подключить новый счётчик и выполнить начисление на контрольном ЛС.

## Что нельзя делать

1. Нельзя объединять `икВидыПриборовУчета` только по имени и единице измерения.
2. Нельзя объединять `икВидыУслуг` по имени, пока не канонизированы `ГруппаУслуг` и `ВидКоммунальногоРесурсаГИСЖКХ`.
3. Нельзя глобально чистить весь `икСправочникиГИСЖКХ`; этот справочник слишком широко используется.
4. Нельзя включать `икУслуги` в автоматическую дедупликацию на этом этапе.
5. Нельзя физически удалять дубли в нашем фиксе; только перепривязка, пометка удаления, безопасное переименование.

## Следующий кодовый шаг

Сделать в обработке новый диагностический блок `[12] Карта зависимостей услуг/приборов` без режима исправления.
Он должен сформировать один отчёт, который объяснит для каждой проблемной группы:

1. какие дубли есть в `Группы услуг`;
2. какие дубли есть в ветке `Справочники ГИС ЖКХ -> Виды коммунальных ресурсов`;
3. какие `Виды услуг` станут одинаковыми после канонизации зависимостей;
4. какие `Виды приборов учета` всё ещё различаются и по каким полям;
5. какие элементы используются живыми приборами/услугами, а какие не используются.

Только после этого отчёта добавлять preview/fix по этапам 2-5.
