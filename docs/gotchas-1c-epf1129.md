# 1C Gotchas: `epf1129`

Назначение:
- фиксировать уже найденные ловушки платформы и проекта;
- не платить повторно за одни и те же ошибки при следующих правках;
- использовать как обязательный чек-лист перед изменениями в `ObjectModule.bsl`, отчётах, восстановлении и фоновых операциях.

## BSL / параметры / свойства

1. `Поле объекта недоступно для записи`
- причина: изменение параметра функции, в который передано свойство выборки/структуры;
- правило: если функция нормализует строку или число, параметр принимать как `Знач`.
- кейсы:
  - `НаименованиеЛС`
  - `НомерЛС`

2. `Поле объекта не обнаружено`
- причина: прямое обращение к необязательному свойству ссылки/объекта;
- правило: спорные свойства проверять через `Попытка/Исключение` или отдельную safe-функцию.
- кейс:
  - `СложнаяНорма`

3. `Метод объекта не обнаружен`
- не использовать неподтвержденные методы коллекций/объектов;
- кейсы:
  - `СодержитКлюч`
  - `ВывестиТекст`
  - `Вывести` с неподходящим параметром

## Табличный документ / Excel

4. Числа в `XLSX` легко превращаются в текст с апострофом
- причина: запись чисел через `ОбластьЯчейки.Текст`;
- совместимое правило:
  - в старой платформе избегать недоступного `Значение`;
  - для числовых колонок писать в `Текст` и ставить `ГоризонтальноеПоложение = ГоризонтальноеПоложение.Право`.

5. Не открывать Excel/LibreOffice автоматически после формирования отчёта
- причина: лишние ошибки клиента и подвисания;
- правило: сохранять файл, путь писать в результат и нижнее окно сообщений формы.

6. В имени `xlsx` и `md` должна быть версия обработки
- правило:
  - `x17_consumers_2025_v25-XXX_...xlsx`
  - `x17_consumers_2025_norm_debug_v25-XXX_...md`

## Запросы / периодические данные

7. `СрезПоследних` по услугам нельзя фильтровать по статусу внутри среза
- неправильно:
  - `СрезПоследних(... И СтатусПодключения = Подключена)`
- правильно:
  - сначала `СрезПоследних` по `ЛС + Услуга`,
  - потом `ГДЕ СтатусПодключения = Подключена`
- иначе можно получить старую подключенную запись уже отключенной услуги.

8. Активность услуги в помесячном отчёте должна читаться по одной и той же контрольной дате
- текущее правило проекта:
  - `КонецДня(КонецМесяца(ПериодОтчета))`
- почему:
  - это соответствует проверке в карточке ЛС “на дату”;
  - одинаково используется для:
    - активности услуги,
    - характеристик,
    - настроек норм,
    - расчета нормы.

9. Оплата в помесячном отчёте считается по месяцу даты платежного документа
- правило:
  - `НАЧАЛОПЕРИОДА(Оплаты.Ссылка.Дата, МЕСЯЦ)`
- не использовать `ПериодОплаты` как главный источник для этого отчёта, если бизнес-вопрос звучит как:
  - “что оплачено в этом месяце”.

10. Для нормы нельзя опираться только на один источник
- приоритет:
  1. настройки по `ЛС + услуга`
  2. настройки услуги через `икРасчетНачислений.ПолучитьНастройкиУслуги(...)`
  3. общие параметры услуги/норматива

11. Тяжёлые выборки и массовые исправления нельзя проектировать как клиентские обходы
- правило:
  - сначала серверный запрос или `SQL read-only`,
  - потом узкий кандидатный набор,
  - потом preview/fix по порциям;
- не тащить большие массивы “на всякий случай” в UI/тонкий клиент.

12. Большие `В (...)` / `IN (...)` не считать автоматически безопасными
- при длинных списках ссылок:
  - дробить на порции,
  - либо использовать staging/временные наборы на серверной стороне;
- ускорение без контроля counts/timing считать неподтвержденным.

13. Для внешних подключений к удаленной `server-base` нельзя использовать `localhost`
- если база находится на другом компьютере, `localhost` с нашей рабочей машины не может быть правильным `Srvr`;
- `Srvr="localhost"` в старых отчетах может означать только внутренний взгляд серверного сеанса 1С на самом сервере;
- для внешних `COM` / `no-UI` / launcher-подключений использовать только реальное сетевое имя или IP сервера 1С.

## Recovery / x17

14. Не смешивать контуры
- `117.x` — отчётность;
- `118.x` — исправление полной базы.

15. Массовый fix только после preview
- особенно для:
  - `прочих характеристик`
  - `видов объектов`
  - `дублей ПВХ`

16. Для спорных случаев использовать контрольные кейсы, а не общие гипотезы
- сначала:
  - конкретный ЛС
  - конкретный месяц
  - конкретная услуга
- потом уже масштабирование на весь отчёт/базу.

17. Не пересжимать контекст до потери предметного смысла
- нельзя выбрасывать:
  - дату периодического среза,
  - конкретный ЛС,
  - конкретную услугу,
  - точное бизнес-правило;
- токены экономить через структурирование и постоянные артефакты, а не через “сильный пересказ всего подряд”.

## Перед изменением отчёта

Обязательная проверка:
1. какие контрольные ЛС затрагиваются;
2. меняется ли дата активности услуги;
3. не ломается ли `xlsx`;
4. остаётся ли `md` отладки;
5. не смешиваются ли активные и неактивные услуги.
