## Plan Review

Rejected approach:

- mass-renumber all duplicate codes/numbers directly in SQL.

Reason:

- 1C object numbering can depend on metadata settings, prefixes, periods, organizations, and document numerators;
- direct SQL writes bypass 1C object logic, caches, registers, and consistency checks;
- duplicate names are not always duplicates;
- many duplicate-code groups are normative data replicated from source bases and may be safe noise rather than update blockers.

Accepted approach:

1. Build a compact diagnostic map of duplicate codes/numbers.
2. Classify findings by update risk and business risk.
3. Implement preview/fix passes in the external processing through 1C object writes.
4. Run each corrective pass on `MergedBase` first.
5. Re-run master diagnostics and update rehearsal after each pass.
