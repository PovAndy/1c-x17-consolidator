# Контрольная точка восстановления x17 и обновления до 36.14

Дата фиксации: 2026-08-14

## Итог

Пользователь подтвердил успешное обновление репетиционной копии объединенной базы x17
`MergedBase` до версии конфигурации `36.14`. Обновление выполнено после завершения
адресных исправлений восстановления и устранения выявленных блокеров обработчиков
обновления.

Эта контрольная точка подтверждает работоспособность процедуры на копии. Она не является
разрешением переносить старые MD5 и количества на будущую свежую копию рабочей базы:
после появления новых данных все ReadOnly-базовые состояния должны быть сформированы заново.

- База: `Srvr="{V8_SERVER}";Ref="MergedBase";`.
- Назначение базы: копия перед обновлением `36.14` и перед ТиС.
- Платформа: `8.3.27.1989`.
- Обработка восстановления: `v25-122.127`.
- Сборка: `build/compiled.epf`.
- SHA-256 сборки: `BEC187ABA8468FB15041175C12F3434AB8A8C8D6ABF3C551F808DB81A7768C21`.
- Исходные локальные базы `x1_XX` использовались только для ReadOnly-сверки и не изменялись.

## Завершенные блоки восстановления

1. Устранены остаточные битые ссылки и системный хвост ТиС; контрольный реестр сведен к
   `0 ссылок + 0 неправильных родителей`.
2. Выполнена дедупликация нумерации документов. Номера документов
   `икОткрытиеЛицевогоСчета`, являющиеся номерами лицевых счетов, были защищены от изменения.
3. Выполнена дедупликация индексных кодов справочников без слияния, удаления и прямой SQL-записи.
4. Устранены блокеры обновления в `РегламентированныеОтчеты`.
5. Устранены блокеры справочника причин увольнения СФР.
6. Устранены целевые дубли оснований увольнения, конфликтующие с классификатором `36.14`.

## Правила переноса на свежую рабочую копию

1. Развернуть свежую рабочую базу в отдельный разрешенный контур; источники `x1_XX`
   оставить строго ReadOnly.
2. Запустить полный набор ReadOnly-проверок восстановления, нумерации, индексных кодов и
   предконтроля обновления.
3. Зафиксировать новые количества и MD5. Любое несовпадение с новым доказанным baseline — STOP.
4. Выполнять только те адресные исправления, для которых новый Preview дал `PASS` и был
   явно разрешен пользователем.
5. После каждой записывающей партии выполнять встроенный постконтроль и повторный ReadOnly.
6. Выполнить диагностический ТиС без исправления. ТиС с исправлением допускается только по
   отдельному решению после анализа полного отчета.
7. Обновить копию до `36.14`, проверить завершение обработчиков обновления, журнал регистрации
   и основные бизнес-сценарии.

Старые MD5 являются доказательствами состояния `MergedBase`, но не шаблоном данных для новой базы.
