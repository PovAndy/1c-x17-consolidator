# Исправление списка характеристик в документе "Принятие помещения к учету"

## Симптом

В `x17` на форме документа `икПринятиеПомещенияКУчету` отображается слишком широкий список характеристик помещения.

## Причина

В процедуре `ЗаполнитьТаблицуХарактеристик()` список характеристик отбирался только по:

1. `ВидОбъектаУчета = &ВидОбъектаУчета`
2. `НЕ ЭтоВычисляемаяХарактеристика`

Этого недостаточно: в пользовательский список попадают служебные и технические элементы того же вида объекта.

## Правильный фильтр

Нужно использовать тот же шаблон, который уже применяется в других формах конфигурации:

1. исключить корневой уровень (`Родитель <> ПустаяСсылка`)
2. группы показывать
3. элементы показывать только если:
   - `ПоказыватьВСпискеХарактеристикОбъектов = Истина`
   - `ЭтоВычисляемаяХарактеристика = Ложь`
4. сортировать по иерархии групп

## Почему data-fix недостаточен

По логам `120.11` data-layer уже вылечен:

1. `Кандидатов на отключение показа: 0`
2. `Уже скрыто в списке: 32`

Это означает, что лишние характеристики уже скрыты флагом в ПВХ, но форма документа продолжает показывать их из-за слишком широкого запроса.

## Проверка после внедрения

1. Открыть документ `Принятие помещения к учету`.
2. Выбрать `Вид объекта учета = Жилые помещения`.
3. Проверить вкладку `Характеристики помещения`.
4. Убедиться, что из списка ушли лишние элементы:
   - `Есть индивидуальный источник отопления (автономное отопление)`
   - `Кол-во легковых автомобилей`
   - `Количество земельных участков для полива`
   - `Количество коров`
   - `Количество кур`
   - `Количество с/х животных`
   - аналогичные районные и технические характеристики
5. Убедиться, что базовые рабочие характеристики остаются доступными.
