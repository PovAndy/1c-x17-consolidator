# Recovery Control Cases

Назначение:
- минимальный набор контрольных кейсов для продолжения работ по полной базе в `118.x`.

## 1. Прочие характеристики

Исходные артефакты:
- `context/recovery/other-pvh/out/restore_map.csv`
- `context/recovery/other-pvh/out/x17_broken.csv`
- `context/recovery/other-pvh/out/x17_broken_candidates.md`

Контроль:
1. `Диагностика прочих хар-к`
2. `Preview прочих хар-к`
3. `Восстановить прочие хар-ки` — только после preview

Исторически подтвержденные безопасные цели:
1. `Марка прибора учёта`
2. `Номер пломбы на узлах присоединения прибора учета ("Гарпун-М")`
3. `Номер антимагнитной пломбы ("МИД" 35.19.18_основной элемент_аА)`
4. `Информация о поверке прибора учёта`


## 1a. Donor-based recovery for broken refs

Use donor exports from clean bases before fixing `x17` directly.

Playbook:
- `docs/x5-broken-refs-playbook.md`

Primary export contour:
- built-in EPF export with `ДополнительныеОбъектыДляВыгрузки`

Secondary helper:
- `scripts/export-other-pvh-recovery-com.win.ps1`

Rule:
1. export live donor data from `x1_*` and optional polygon base through the EPF exchange contour first;
2. normalize and refresh `restore_map.csv`;
3. test on polygon first;
4. only then apply to `x17_pg2`.

## 2. Характеристики объектов учета / вкладка ЛС

Проблема:
- раздутый показ характеристик;
- живые дубли `ПВХ.икХарактеристикиОбъектовУчета`.

Контроль:
1. не запускать массовые fix вслепую;
2. сначала диагностировать группы дублей;
3. сверять на живых ЛС, где видна лишняя строка.

## 3. Виды объектов / ПВХ

Статус:
- основной слой уже чистился отдельно;
- повторно трогать только по новым доказательствам из диагностики.

## 4. Правило работы

Для `118.x`:
1. сначала read-only диагностика;
2. потом preview;
3. только потом safe-fix;
4. после каждого fix — контроль на живых карточках и в отчетах.
5. heavy-fix выполнять порциями, а не одним массовым проходом.
6. все спорные ускорения подтверждать фактическими данными, а не интуицией.

## 5. Правило производительности recovery

1. Узкий набор кандидатов формировать до запуска fix.
2. Длинные списки ссылок/элементов дробить на порции.
3. Держать транзакции короткими и предметными.
4. Не использовать клиентские обходы больших выборок, если то же можно выразить серверным запросом.
5. Сначала лечить структуру:
- дубли ПВХ,
- ссылки на удалённые `[ДУБЛЬ]`-элементы,
- точные дубли строк регистров,
и только потом хвост broken refs.
