# Ошибка отчёта по индивидуальным приборам учета из-за дубля ПВХ

## Симптом

При открытии отчёта `икОтчетПоИндивидуальнымСчетчикам` база выдаёт ошибку:

```text
Ошибка при вызове конструктора (ПолеКомпоновкиДанных)
...
по причине:
Ошибка в пути к данным: [Справочник "Индивидуальные приборы учета"].[ДУБЛЬ] Марка прибора учёта
```

## Что это значит

Отчёт динамически добавляет характеристики индивидуальных приборов учета в СКД через
`ОбщийМодуль.икХарактеристики`.

Путь к данным строится из имени характеристики. Если в рабочей ветке ПВХ остаётся элемент:

- `[ДУБЛЬ] Марка прибора учёта`

то в путь к данным попадает строка:

- `[Справочник "Индивидуальные приборы учета"].[ДУБЛЬ] Марка прибора учёта`

и `ПолеКомпоновкиДанных` не может создать такое поле.

## Корневая причина

В рабочей базе `x17` под веткой характеристик индивидуальных приборов учета остались
живые или невычищенные элементы `[ДУБЛЬ] ...`.

По накопленным логам уже подтверждалось наличие дублей по характеристике:

- `Марка прибора учёта`
- коды группы: `000000036, 000000037, 000000038, 000000039, 000000040, 000000041, 000000060, 000000061`
- отдельные `[ДУБЛЬ]`-элементы уже встречались в рабочей базе:
  - `[ДУБЛЬ] Марка прибора учёта [код=000000039]`
  - `[ДУБЛЬ] Марка прибора учёта [код=000000060]`

## Что исправляет проблему сейчас

Нужно чистить именно ПВХ `икХарактеристикиПрочихОбъектов`, а не регистр битых ссылок.

### Правильный порядок

1. Найти все элементы `[ДУБЛЬ] ...` под веткой:
   - `Справочник "Индивидуальные приборы учета"`
2. Для каждого такого элемента:
   - перепривязать ссылки на канонический элемент, например:
     - `Марка прибора учёта`
3. После того как живых ссылок не осталось:
   - физически удалить дубль
   - или убрать его из рабочей ветки, если прямое удаление пока невозможно
4. Повторно открыть отчёт

## Что не поможет

1. Повторные прогоны `Восстановить прочие хар-ки`
   - этот дефект не про битые ссылки регистра
2. Переписывание `restore_map.csv`
   - проблема не в карте замен, а в том, что сам отчёт подхватывает дубль ПВХ

## Правильный hardening fix в конфигурации

Даже после чистки данных база остаётся уязвимой, если похожий дубль появится снова.

Поэтому в конфигурации нужно дополнительно поправить код `ОбщийМодуль.икХарактеристики`:

1. при добавлении характеристик в СКД игнорировать элементы:
   - с `ПометкаУдаления = Истина`
   - с префиксом `[ДУБЛЬ]`
2. не строить `ПолеКомпоновкиДанных` по таким именам

Это не заменяет чистку данных, но защищает отчёт от повторного падения.

## Практическое решение

Если нужна самая быстрая стабилизация рабочей базы:

1. сначала запустить в обработке кнопку:
   - `Санировать имена дублей ПВХ`
2. она массово заменит имена вида:
   - `[ДУБЛЬ] Марка прибора учёта`
   на:
   - `ДУБЛЬ Марка прибора учёта`
3. затем повторно проверить открытие отчёта;
4. если отчёт открылся, дальше уже спокойно дочищать ссылки и удалять дубли правильно;
5. после этого уже делать кодовый hardening в конфигурации, чтобы ошибка не вернулась.

## Что добавлено в обработку

В `v25-118.34` добавлена отдельная кнопка:

- `Санировать имена дублей ПВХ`

Она:
1. не убирает признак дубля полностью;
2. убирает только квадратные скобки из префикса:
   - было: `[ДУБЛЬ] ...`
   - становится: `ДУБЛЬ ...`
3. не меняет ссылки;
4. нужна именно как быстрый стабилизирующий шаг для отчётов и СКД.
