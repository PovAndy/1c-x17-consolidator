Используем четыре класса:

1. `unsafe_live`
   - активных элементов в дубль-группе больше одного;
   - есть живые ссылки в рабочем регистре;
   - это следующий обязательный corrective-pass.

2. `live_no_refs`
   - активных элементов больше одного;
   - в focused-рабочем регистре ссылок не найдено;
   - это не безобидно, но уже не первый corrective-приоритет.

3. `tail_with_refs`
   - активен только один элемент, но хвост дублей всё ещё имеет живые ссылки;
   - для текущего focused-pass не выявлено.

4. `tail_no_refs`
   - активен только один элемент или вообще ни одного;
   - живых ссылок нет;
   - это хвост на позднюю чистку после живых дублей.
