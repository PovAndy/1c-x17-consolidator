# 1c-x17-consolidator

**High-integrity database merger and deduplication pipeline for 1C 8.3 / GKH monolith.**

Консолидатор 1С: обработка внешняя (EPF) «ВыгрузкаЗагрузкаДанныхXMLАдаптивная» +
инструментарий восстановления целостности объединённой базы данных x17.

English overview: [README.en.md](README.en.md). Russian is the canonical
detailed project reference; the English file is its reviewed navigation
companion.

Проект решает задачу слияния семнадцати локальных баз 1С (ГКХ / ЖКХ монолит) в единую
объединённую базу с гарантией целостности ссылочной целостности, дедупликации
справочных данных и восстановления битых ссылок.

## Назначение

1. **Слияние баз** — перенос данных из 17 локальных баз в единую объединённую базу
   через адаптивную выгрузку/загрузку XML (внешняя обработка
   «ВыгрузкаЗагрузкаДанныхXMLАдаптивная»).
2. **Дедупликация** — поиск и разрешение дублей справочников, характеристик, лицевых
   счетов и индексов *без* слияния, удаления и прямой SQL-записи (только
   через штатные механизмы переноса).
3. **Восстановление целостности** — устранение битых ссылок, неправильных родителей,
   остатков ТиС, дублей нумерации документов (с защитой номеров лицевых счетов).
4. **Подготовка к обновлению** — устранение блокеров обработчиков обновления
   конфигурации (регламентированные отчёты, причины увольнения СФР, дубли оснований
   увольнения, конфликты с классификатором).

## Для какой конфигурации

Обработка применялась к монолиту ГКХ (ЖКХ) на платформе 1С:Предприятие 8.3
(8.3.27.1989) для конфигурации **36.14**. Схемы справочников и регистров типовые для
данного класса баз; точный состав метаданных см. в `docs/` и `sql/readonly/`.

## Нововведения и разработки

### Обработка (EPF, `src/`)
- Адаптивный выбор объектов метаданных и аналитик для выгрузки/загрузки.
- Управление ключами аналитики (справка, картинка ключей) для корректного переноса.
- Защита номеров лицевых счетов при дедупликации нумерации документов
  (`икОткрытиеЛицевогоСчета`).
- Дедупликация индексных кодов справочников без слияния/удаления/прямого SQL.
- Идентификация целевого контура базы (объединённая x17) в логике обработки.

### Инструментарий (`scripts/`, `sql/readonly/`)
- COM-мост в Windows (PowerShell) для диагностики баз: пробы метаданных, полей,
  предопределённых значений, типов представлений.
- Read-only SQL-диагностика PostgreSQL: схема, топ-отношения, поиск по именам,
  анализ удалённых ссылок по характеристикам (`_inforg36811`, `_reference209`).
- Инвентаризация дублей ПВХ и глобальных дублей справочников.
- Сверка эталонных структур лицевых счетов и типов представлений между базами.
- Анализ остатков ТиС и сбор донорских фактов восстановления.
- Сборка/разборка EPF: `compile.win.ps1`, `decompile.win.ps1`, `compile.sh`,
  `decompile.sh` (vrunner).

### Методики (задокументированы в `docs/`)
- Матрица стандартной очистки дублей (`standard-duplicate-cleanup-matrix`).
- План стабилизации глобальных дублей x17 и разрыв расчёта счётчиков.
- Плейбуки восстановления битых ссылок (`broken-refs-pass-12019-runbook`,
  `x5-broken-refs-playbook`, `manual-tail-11832`).
- Кейсы: новый счётчик 14-123, ошибка ИПУ из-за дубля ПВХ, оценка проблемы дублей
  индексов, путь восстановления начислений по новым счётчикам.

## Рабочая среда

Среда не публикуется; ниже — краткое описание для воспроизводимости.

- **ОС**: Linux (WSL2 Ubuntu) + Windows bridge для 1С COM.
- **1С**: платформа 8.3.27.1989, сервер 1С (`8.3.27.1964` — Windows bridge).
- **Исполнение BSL**: OneScript (`oscript`) + `vrunner` (компиляция EPF).
- **Python**: виртуальные окружения для SQL-диагностики, MCP-серверов, RAG.
- **Доступ к базам**: 17 локальных файловых баз (read-only), объединённая база —
  через серверный контур (диагностический read-only).
- **Конфигурация**: переменные окружения (см. `.env.example`, `.env.gemini.example`,
  `.env.openrouter.example`); реальные секреты хранятся только локально.
- **MCP/инструменты**: код-индекс, диагностика 1С, SQL-диагностика.

### Плейсхолдеры вместо секретов

Все внутренние имена хостов, баз и абсолютные пути в публикуемых исходниках заменены
на плейсхолдеры: `{V8_SERVER}`, `{V8_BASES}`, `{SHARE_ROOT}`, `{PROJECT_ROOT}`,
`{HOME}`, `{BRIDGE_HOST}`, `{V8_PORT}`, `{HTTP_PROXY}`, `MergedBase`, `ServedBase`.
Реальные значения хранятся локально и в репозиторий не попадают.

## Сборка и использование

1. Скопируйте `.env.example` в `.env` и заполните пути к 1С/базам.
2. На Windows-мосте выполните сборку:
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/compile.win.ps1
   ```
   Либо в Linux через vrunner: `scripts/compile.sh`.
3. Загрузите полученный EPF в объединённую базу и выполните выгрузку/загрузку по
   методике `docs/`.
4. Диагностику дублей и битых ссылок запускайте read-only скриптами `sql/readonly/`
   и `scripts/*.py` (примеры команд — в соответствующих документах).
